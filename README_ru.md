# ARTEMIDA — Гибридная поисковая система

## О системе

ARTEMIDA (Advanced Retrieval Through Enhanced Multi-method Intelligent Document Architecture) — это гибридная поисковая система, объединяющая множество подходов к информационному поиску для достижения максимальной релевантности результатов.

Традиционные поисковые системы используют один метод поиска:
- **Лексический поиск** (BM25) хорошо находит документы с точными совпадениями слов, но не понимает синонимы и смысл
- **Векторный поиск** (TF-IDF) учитывает частоту слов, но неcaptures семантику
- **Нейросетевой поиск** понимает смысл, но может пропустить точные терминологические совпадения

### Решение

ARTEMIDA объединяет все эти методы и добавляет машинное обучение для интеллектуального ранжирования:

1. **Лексический поиск (BM25)** — находит документы с точными терминами
2. **Векторный поиск (TF-IDF + SVD)** — косинусное сходство в векторном пространстве
3. **Нейросетевой поиск (multilingual-e5)** — семантическое понимание, включая русский язык
4. **HNSW индекс** — быстрый приближенный поиск по векторам
5. **Гибридный поиск** — объединение BM25 и косинусного сходства с настраиваемым весом α
6. **Learning to Rank (LTR)** — модель градиентного бустинга (LightGBM) для переупорядочивания результатов
7. **Smart Hybrid** — автоматический выбор оптимального метода на основе анализа запроса

### Архитектура

```
Запрос пользователя
       ↓
[Query Analyzer] — анализ языка, длины, типа запроса
       ↓
┌─────────────────────────────────────────────┐
│  Автоматический выбор метода поиска        │
│  - Русский текст      → Neural (multilingual) │
│  - Короткий термин    → Lexical (BM25)        │
│  - Смысловой запрос   → LTR или Hybrid        │
└─────────────────────────────────────────────┘
       ↓
┌─────────────────────────────────────────────┐
│  Методы поиска:                             │
│  1. Lexical: инвертированный индекс + BM25 │
│  2. TF-IDF: косинусное сходство векторов   │
│  3. Neural: sentence-transformers           │
│  4. HNSW: приближенный векторный поиск     │
│  5. Hybrid: BM25 + Cosine (параметр α)     │
│  6. LTR: LightGBM на множестве признаков   │
└─────────────────────────────────────────────┘
       ↓
[Ранжирование] — объединение и сортировка результатов
       ↓
Топ-5 релевантных документов
```

### Корпус документов

В качестве текста документа используется аннотация (abstract) научной статьи с arXiv. Аннотация содержит ключевые термины и семантическое ядро работы, что достаточно для задач информационного поиска, при этом избегает проблем с лицензией CC-BY на полные тексты PDF.

## Настройка через .env файл

Система поддерживает настройку параметров обработки текста через файл `.env`. Это позволяет легко настроить мультиязычность, стемминг, стоп-слова и другие параметры без изменения кода.

### Создание .env файла

Создайте файл `.env` в корне проекта и настройте параметры:

```bash
# Если файл .env не существует, скопируйте из .env.example
cp .env.example .env
notepad .env
```

### Доступные параметры

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `DEFAULT_LANGUAGE` | `auto` | Язык обработки: `en` (английский), `ru` (русский), `multilingual` (оба языка), `auto` (автоопределение) |
| `USE_STEMMING` | `true` | Включить/выключить стемминг/лемматизацию |
| `REMOVE_STOPWORDS` | `true` | Удалять ли стоп-слова (например, "the", "is", "в", "и") |
| `MIN_TOKEN_LENGTH` | `2` | Минимальная длина слова для обработки |
| `MORPH_CACHE_SIZE` | `10000` | Размер кэша для морфологического анализа (оптимизация производительности) |

### Пример .env файла

```env
# Язык по умолчанию для обработки текста
DEFAULT_LANGUAGE=multilingual

# Использовать ли стемминг
USE_STEMMING=true

# Удалять ли стоп-слова
REMOVE_STOPWORDS=true

# Минимальная длина токена
MIN_TOKEN_LENGTH=2

# Размер кэша для pymorphy3 (морфологический анализатор русского языка)
MORPH_CACHE_SIZE=10000
```

### Рекомендации по настройке

**Для английского текста:**
```env
DEFAULT_LANGUAGE=en
REMOVE_STOPWORDS=true
```

**Для русского текста:**
```env
DEFAULT_LANGUAGE=ru
REMOVE_STOPWORDS=true
```

**Для мультиязычного поиска (по умолчанию):**
```env
DEFAULT_LANGUAGE=multilingual
REMOVE_STOPWORDS=true
```

**Для ускорения обработки (меньше кэш):**
```env
MORPH_CACHE_SIZE=5000
```

**Для экспериментов (без стемминга):**
```env
USE_STEMMING=false
```

### Как используется

- Параметры из `.env` применяются в `TextProcessor` при предобработке текста
- Если файл `.env` не найден, система использует значения по умолчанию
- Изменения в `.env` вступают в силу после перезапуска программы

## Умный гибридный поиск (Smart Hybrid)

Команда `smart-hybrid` — это автоматический выбор оптимального метода поиска на основе анализа запроса. Система анализирует язык, длину и тип запроса для выбора лучшего подхода.

### Логика выбора метода

| Тип запроса | Метод | Причина |
|-------------|-------|--------|
| Русский текст | Neural (multilingual-e5) | Нейросетевая модель понимает семантику на русском языке |
| Короткий термин (1-3 слова) | Lexical (BM25) | Точные совпадения важнее семантики для терминов |
| Смысловой запрос (вопрос, описание) | LTR (LightGBM) | Модель ML учитывает множество признаков для лучшего ранжирования |
| Смысловой запрос (без LTR) | Hybrid (BM25 + Cosine) | Объединение лексического и векторного поиска |
| Общий случай | Hybrid (α=0.5) | Баланс между точными совпадениями и семантикой |

### Признаки для анализа

- **Язык запроса** — наличие русских символов → нейросетевой поиск
- **Длина запроса** — количество слов < 4 → лексический поиск
- **Тип запроса** — вопросительные слова (what, how, why) → LTR или гибридный

### Использование

```bash
python main.py smart-hybrid
```

В интерактивном режиме:
1. Введите поисковый запрос
2. Система автоматически выберет метод и покажет причину
3. Можно принудительно указать метод: `neural`, `lexical`, `hybrid`, `ltr`, `hnsw`

Пример:
```
Запрос: 'machine learning algorithms'
Выбранный метод: ltr (причина: conceptual_query_with_ltr)
```

### Преимущества

- **Автоматизация** — не нужно вручную выбирать метод для каждого запроса
- **Адаптивность** — учитывает язык и тип запроса
- **Fallback** — если метод недоступен, автоматически переключается на гибридный

## Как работает гибридный поиск

### Формула гибридного ранжирования

Гибридный поиск объединяет лексический (BM25) и векторный (косинусное сходство) методы:

```
hybrid_score = α × normalized_BM25 + (1 − α) × normalized_cosine
```

Где:
- **α** — вес лексического поиска (0 ≤ α ≤ 1)
- **normalized_BM25** — нормализованная оценка BM25 в диапазоне [0, 1]
- **normalized_cosine** — нормализованное косинусное сходство в диапазоне [0, 1]

Нормализация выполняется по формуле Min-Max:
```
normalized_score = (score − min_score) / (max_score − min_score)
```

### Этапы гибридного поиска

1. **Получение кандидатов** — лексический и векторный поиск возвращают по 20 документов
2. **Объединение** — удаление дубликатов, объединение списков
3. **Вычисление оценок** — BM25 и косинусное сходство для каждого кандидата
4. **Нормализация** — приведение оценок к диапазону [0, 1]
5. **Гибридная оценка** — взвешенная сумма по формуле
6. **Ранжирование** — сортировка по убыванию гибридной оценки

### Настройка параметра α

- **α = 1.0** — только лексический поиск (точные совпадения)
- **α = 0.0** — только векторный поиск (семантика)
- **α = 0.5** — баланс между точностью и смыслом
- **α = 0.7** — упор на точные термины
- **α = 0.3** — упор на семантическое сходство

## Learning to Rank (LTR)

LTR — это подход машинного обучения для переупорядочивания результатов поиска. Система обучается на размеченных данных, где для каждой пары "запрос-документ" указана релевантность (1 — полностью соответствует, 2 — частично, 3 — не соответствует).

### Признаки для модели

Модель LightGBM использует следующие признаки:

1. **BM25 score** — оценка лексического релевантности
2. **TF-IDF cosine** — косинусное сходство TF-IDF векторов
3. **Neural cosine** — косинусное сходство нейросетевых векторов
4. **Query word overlap in text** — доля слов запроса в тексте документа
5. **Query word overlap in title** — доля слов запроса в заголовке
6. **Document length** — длина документа в токенах

### Процесс обучения

1. **Подготовка данных** — генерация пар query-doc с оценками релевантности
2. **Разделение** — 30 запросов для обучения, 10 для тестирования
3. **Обучение** — LightGBM градиентный бустинг на деревьях
4. **Оценка** — Precision@5, nDCG@5 на тестовой выборке

### Преимущества LTR

- **Учет множества факторов** — модель учитывает все признаки одновременно
- **Обучаемость** — качество улучшается с ростом размеченных данных
- **Интерпретируемость** — можно увидеть важность каждого признака

## Зачем нужна эта система?

### Ограничения традиционных подходов

| Метод | Преимущества | Недостатки |
|-------|-------------|------------|
| **BM25** | Находит точные совпадения слов, быстрая | Не понимает синонимы, не учитывает семантику |
| **TF-IDF** | Учитывает частоту слов | Не понимает смысл, игнорирует порядок слов |
| **Нейросети** | Понимают семантику, работают с синонимами | Могут пропустить точные термины, требуют ресурсов |
| **HNSW** | Быстрый поиск по большим векторам | Это приближенный метод, есть потеря точности |

### Что дает ARTEMIDA

1. **Комбинирование сильных сторон** — каждый метод компенсирует недостатки других
2. **Адаптивность** — система выбирает лучший метод для каждого запроса
3. **Машинное обучение** — LTR модель учится на данных и улучшается со временем
4. **Мультиязычность** — работает с русским и английским языками
5. **Исследовательский потенциал** — бенчмарки для сравнения методов

### Применение

- **Научный поиск** — поиск по научным статьям и документам
- **Корпоративные базы знаний** — интеллектуальный поиск по документам организации
- **Образовательные системы** — поиск учебных материалов
- **Исследования IR** — платформа для экспериментов с методами поиска
